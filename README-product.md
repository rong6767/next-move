# 下一站 · 求职工作台

中文个人求职 Site。私人访问，ChatGPT 登录，Cloudflare D1 保存岗位与进展，Site MCP 为 dot 提供同一份数据的维护工具。

## 主要流程

1. 添加或导入岗位，保存 JD 快照、来源和申请链接。
2. 待评估 → 待投递 → 已投递 → 初筛 → 面试 → Offer；也支持未通过、撤回和归档。
3. 记录使用的简历版本、联系人、下一步行动与跟进日期。
4. 使用列表、看板和到期提醒查看进展。时间线保存状态变化和笔记。
5. 导出 JSON 备份或 CSV 列表，JSON 导入按岗位/链接去重并保留已有记录。

本源码分发不附带个人候选岗位资料；`lib/seed-jobs.json` 保持为空数组。用户可在自己的工作台中添加岗位或导入自己的 JSON 备份。导入不会更新已存在的岗位，也不会把候选当作已投递。

## dot 维护

发布时 `capabilities: ["mcp"]` 创建此 Site 的私有插件。安装或连接后，dot 可列出、添加、更新岗位，读取 JD，记录进展，归档或恢复岗位，查询到期跟进，导入已有候选。

例如：“把这个岗位加入下一站，保存完整 JD，优先级设为高。”“我已于 10 月 12 日投递该岗位，使用 SDE 简历，下周一提醒我跟进。”“查看今天需要跟进的申请。”

工具只维护记录，不向雇主提交申请或发送消息。持续定时检查需要另外配置自动化；本站页面不会宣称已在后台持续执行。

## 开发

保留 Vinext/Sites starter 的 `sites()` 集成。`npm run dev` 支持本地 ChatGPT 模拟登录；生产身份由 Sites 注入。`npm run db:generate` 生成 D1 迁移；构建与发布按 Sites 技能执行。数据库按 Site 用户 ID 隔离，API 写请求检查来源，记录版本用于防止并发覆盖。平台身份、源仓库凭据和任何服务令牌不得写入源码。

参考资料均未修改。Site 身份和 DB/MCP 声明在 `.openai/hosting.json`；运行状态、构建输出与本地数据库不进入源仓库。
