# 下一站 · Next Move

一个支持中文和英文的个人求职工作台，用于保存岗位和完整 JD，按公司整理机会，追踪投递、面试与跟进进度。

[English](README.md)

## 主要功能

- **按公司分组**：同一公司的多个岗位归在同一条目下，展开查看；各岗位的 JD、状态和时间线独立保存。
- **多种视图**：公司、岗位列表和进度看板。支持 JD 内容搜索、进度与优先级筛选、排序和分页。
- **投递管理**：记录真实投递日期、简历版本、联系人、下一步行动和沟通笔记。
- **跟进日程**：查看逾期、今日到期和后续事项；日期按多伦多时区计算。
- **中英切换**：界面和导出列名随语言切换，浏览器记住偏好，保存的岗位原文保持不变。
- **导入与备份**：JSON 保留完整时间线；CSV 导出全部匹配结果，不受当前页限制。
- **dot 协作**：通过私人 Site MCP 工具维护与网站相同的一份记录。

## 本地运行

需要 Node.js 22.13 或更新版本。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。本地预览支持通过 `/signin-with-chatgpt?return_to=/` 模拟登录，生产环境由 Sites 管理 ChatGPT 登录。

```sh
npm run check:types
npm run check:i18n
npm run build
```

构建输出位于 `dist/`，可用 `npm start` 运行本地生产预览。修改数据库结构后，使用 `npm run db:generate` 生成迁移。

## 数据与协作

岗位 JD、笔记、来源、标签和已有时间线保留原文。语言切换只改变界面，不改写记录；两种语言共用同一套 API 状态值。

“标记已投递”用于记录已经完成的申请，不会向雇主发送简历。dot 工具仅维护记录，不代为投递或发送消息。跟进日期会显示在工作台，后台定时提醒需要另外配置自动化。

导入时跳过已有岗位；更新时通过记录版本避免并发覆盖；归档岗位可以恢复。

## GitHub 源码与部署

GitHub 分发版本不包含个人候选清单、数据库、备份、凭据或现有 Site 的项目绑定，候选种子为空数组。现有私人网站继续使用原来的项目绑定与用户数据。

部署自己的副本时，按 Sites 流程注册新 Site，并把返回的项目 ID 写入 `.openai/hosting.json`；保留 `DB` 绑定和 `mcp` 能力声明。数据库迁移应与对应源码版本一起部署。

历史阶段保留原开发日期；移除个人资料和部署身份后，分发版本的提交哈希会与原始源码不同，详情见 GitHub 分发版本中的 `docs/source-history.md`。
